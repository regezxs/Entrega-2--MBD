Critérios da atualização

Os nomes de coluna e os registros vieram da planilha, enquanto os relacionamentos foram alinhados ao DER. Campos adicionais para relacionamentos foram introduzidos quando necessário. O dicionário anterior foi usado para contextualizar as descrições dos campos equivalentes.

Compatibilidade: estados e situações são VARCHAR, pois a planilha traz diferentes valores e grafias. CPFs e CNPJs são armazenados com pontuação, tal como fornecidos. Dados de planilha são fictícios.

Ajustes documentados: atendimento.id_agendamento é vinculado quando a descrição permite correspondência consistente; manutencao.id_funcionario permanece nulo porque a planilha identifica empresas externas por nome; movimentacao_estoque.id_compra e id_producao derivam de origem (Compra #N / Produção #N).

Importante: material.quantidade_estoque corresponde ao saldo apresentado na planilha; as movimentações são históricas e não são reaplicadas automaticamente no script de importação, para evitar duplicar os saldos.

Regras e validações do script

  • Cada tabela tem chave primária auto incremental, inclusive tabelas associativas com coluna id presente na planilha.
  • Chaves estrangeiras protegem os vínculos, com ON DELETE RESTRICT e ON UPDATE CASCADE.
  • Valores monetários e quantidades possuem CHECK para impedir números negativos.
  • CPF, CNPJ e número de série recebem unicidade; salas possuem unicidade por andar e número.
  • Os dados são importados sem sobrescrever a base anterior. O script não cria views/triggers da entrega antiga, pois a versão atual documenta somente os objetos definidos no novo SQL.
  • Dados clínicos identificáveis exigem controle de acesso e atenção à LGPD em produção; os dados fornecidos são fictícios.
